# ChannelGuard

ChannelGuard 是一个基于 LSPosed 的 Android 通知频道管理模块。它可以按应用管理通知频道，并根据关键词规则自动关闭常见的运营、营销和推广类频道。

> 项目目前以 MIUI / HyperOS 的通知服务为主要目标。其他 Android ROM 或系统版本尚未逐一验证。

## 功能

- 查看设备上已安装的应用，并按应用名称或包名搜索。
- 查看应用已观测到的通知频道、频道 ID 和重要性。
- 手动关闭或开启单个通知频道。
- 启用智能模式，根据规则自动关闭命中的频道。
- 从规则仓库手动同步规则；同步失败时继续使用本地内置规则。
- 将当前规则应用到设备上已有的通知频道。
- 为常见功能频道配置排除关键词，减少误拦截。

## 工作方式

模块运行在 Android 系统框架进程中，监听通知频道创建和查询流程：

1. 应用创建通知频道时，ChannelGuard 根据手动设置和智能规则判断是否关闭该频道。
2. 查询通知频道时，模块记录频道信息，供管理界面展示。
3. “立即扫描并应用”会扫描已安装应用的现有频道，并关闭符合规则的频道。

规则优先级为：**手动设置 > 智能规则**。手动规则对单个“应用 + 频道 ID”生效；智能规则在智能模式开启时匹配频道名称和频道 ID。

智能匹配先检查排除词：只要任一排除词命中，该频道就不会因正向关键词被自动关闭。没有命中排除词时，任一启用规则的正向关键词命中即视为匹配。

## 环境要求

- Android 8.0（API 26）或更高版本。
- LSPosed，支持 Xposed API 82。
- 建议使用 MIUI / HyperOS，并在 LSPosed 中将作用域设置为“系统框架（android）”。
- 智能规则同步需要网络连接；手动频道管理和内置规则不依赖同步成功。

## 安装与启用

### 获取 APK

从项目 GitHub Releases 下载已发布的 APK。若仓库尚无 Release，可按下方“从源码构建”自行生成。

### 配置 LSPosed

1. 安装 ChannelGuard APK。
2. 在 LSPosed 中启用 ChannelGuard 模块。
3. 将作用域勾选为“系统框架”（包名 `android`）。
4. 重启设备，使系统框架 Hook 生效。
5. 打开 ChannelGuard。若出现“模块未激活”提示，请先检查模块开关、作用域和重启状态。
6. 确认系统允许应用查询已安装应用。项目在 Manifest 中声明了 `QUERY_ALL_PACKAGES`；若应用列表不完整，请检查系统的应用可见性或 ROM 限制。

> 本模块依赖系统通知服务 Hook。仅安装 APK、但未在 LSPosed 中启用并勾选系统框架作用域时，频道管理功能不会正常工作。

## 使用方法

### 管理应用和频道

1. 在首页浏览或搜索应用。搜索支持应用名称和包名。
2. 点击应用进入“通知频道”页面。
3. 使用频道右侧开关控制频道状态：
   - 开：频道保持开启，通知可以正常送达。
   - 关：频道被手动拦截。
4. 频道页面会显示已观测频道数量、手动拦截数量和未手动拦截数量。

频道列表来自系统通知服务中已查询并保存的频道。首次使用或某个应用没有频道记录时，先确认模块已生效，再打开对应应用并触发一次通知；随后返回列表查看。应用也可能尚未创建通知频道。

### 使用智能模式

1. 打开首页右上角的设置。
2. 在“智能模式”中开启“自动拦截匹配频道”。
3. 可在“规则库”中手动同步规则。同步成功后会显示规则数量、来源和最近同步时间；同步失败时仍可使用本地内置规则。
4. 点击“立即扫描并应用”，将当前规则应用到设备上已有的频道。

智能模式会在应用创建频道时自动判断；“立即扫描并应用”用于处理扫描时已经存在的频道。批量扫描结果会显示应用数、频道数和本次关闭的频道数。

## 从源码构建

项目使用 Android Gradle Plugin、Kotlin 和 Jetpack Compose。使用仓库自带的 Gradle Wrapper 构建：

```powershell
.\gradlew.bat :app:assembleDebug
```

Debug APK 输出路径：

```text
app/build/outputs/apk/debug/app-debug.apk
```

运行单元测试：

```powershell
.\gradlew.bat :app:testDebugUnitTest
```

在 macOS 或 Linux 上可使用：

```bash
./gradlew :app:assembleDebug
./gradlew :app:testDebugUnitTest
```

## 规则来源

默认云端规则地址：

[`ChannelGuard/rules.json`](https://raw.githubusercontent.com/azheng95/ChannelGuard/main/rules.json)

本地规则文件保存在应用私有目录的 `files/rules/` 下。首次启动或本地没有成功同步的规则时，模块使用代码内置规则。

## 常见问题

### 首页提示模块未激活

检查 LSPosed 中是否已启用 ChannelGuard、是否勾选“系统框架（android）”作用域，并在配置后重启设备。

### 应用列表为空或应用数量很少

确认系统没有限制应用可见性，并检查 ROM 对 `QUERY_ALL_PACKAGES` 的处理。首页刷新按钮可以重新读取应用列表。

### 应用详情页没有频道

模块只展示已经从系统通知服务观测并保存的频道。确认 Hook 已生效后，打开目标应用并触发一次通知，再重新进入详情页。

### 智能模式没有关闭频道

确认智能模式已开启，并检查频道名称或频道 ID 是否包含规则正向关键词。若频道命中任一排除关键词，排除规则优先，不会被智能规则关闭。也可以在设置页点击“立即扫描并应用”处理已有频道。

### 规则同步失败

检查网络连接及对 GitHub Raw 内容的访问。同步失败不会删除已有的云端规则文件；首次同步失败时会继续使用内置规则。

## 已知限制

- 系统通知服务的内部 API 和 Hook 点可能随 ROM、Android 版本变化；目前不保证所有设备均兼容。
- 已关闭的系统通知频道可能受 Android 行为限制，应用侧不一定允许重新提高其重要性。手动打开开关会清除 ChannelGuard 的手动拦截规则，但不保证恢复系统中已被用户或系统关闭的频道。
- “立即扫描并应用”负责关闭命中频道，不会批量恢复此前已关闭频道。
- 频道列表取决于系统服务已返回并保存的数据；尚未创建或尚未观测到的频道不会显示。
- 项目尚未提供隐私政策、自动更新机制或多语言界面。
